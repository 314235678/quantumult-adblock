# ============================================================
# 功能豁免清单 (allowlist.txt)
# ------------------------------------------------------------
# 语法（每行一个，空格后跟可选标签，默认 full）：
#   域名          → 完全豁免：不进域名拒绝层，也不进 MitM 解密列表
#   域名 mitm     → 仅豁免 MitM：域名仍可被域名规则拒绝，但不做中间人解密
#
# 为什么必须有这一层：
#   上游清单是全网的、无差别收录的。"广告域名"和"业务域名"在国内 App 里经常
#   混在同一个主域下（api.m.jd.com 既派发商品数据也下发开屏广告素材）。
#   一旦整域拦掉，App 表现就是"没网"：白屏、加载不出来、点了没反应，
#   而用户几乎不可能想到是去广告规则干的。
#   这里人工圈定"宁可漏拦、不可错杀"的域名，优先级高于任何上游清单。
# ============================================================

# ---------- 京东（2026-11 故障复盘：三处同时踩踏）----------
# 事故根因：
#   1) HOST-KEYWORD,mapi.m.jd.com,REJECT
#      关键词是「子串匹配」，等于把京东 App 主 API 全部拒绝
#   2) HOST-SUFFIX,360buyimg.com,REJECT
#      这是京东图片 CDN，商品图、头图、详情图全在这里，拦掉=全站白图
#   3) MitM 列表里含 api.m.jd.com / dns.jd.com / img.360buyimg.com / m.jd.com
#      京东 App 对关键接口做了证书固定（SSL Pinning），被中间人解密后
#      直接拒绝连接 —— 这条最隐蔽，报错信息看起来就像"网络异常"
#
# 取舍：jd.com 全域豁免后，京东自己的开屏广告也拦不掉了。
# 广告和业务同域，域名层无法区分，只能功能优先。
jd.com
360buyimg.com
3.cn
